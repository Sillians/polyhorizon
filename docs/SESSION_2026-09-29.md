## Cancellation changes

- Consumer orchestration is now async; no long-lived `asyncio.to_thread` task
  survives flow cancellation. Context exit stops its Kafka background thread.
- Pipeline failure/cancellation cancels and awaits both sibling tasks.
- Health reporting calls the underlying function with bounded network timeouts,
  without submitting work to a torn-down Prefect task runner.
- Producer shutdown runs even when its health task fails during cleanup.
- Kafka consumer close has a five-second timeout.
- Spark runs in a dedicated process group; termination/cancellation sends TERM,
  waits up to ten seconds, escalates to KILL, and reaps the child. SIGTERM handling
  is installed on the main thread and restored afterward.

This fixes cleanup, not data continuity during laptop sleep. Keep the machine
awake, powered and connected throughout the next session and post-close drain.
Start before market open, preserve checkpoints, and do not relax qualification.
No production materialization, training, promotion or automatic session launch
is part of this repair.
