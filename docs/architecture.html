PolyHorizon / System map

Market events → governed forecasts

Intraday collection. Qualified, post-close publication. A governed TFT model serves forecasts using the same feature contract it was trained on.

01 / Collect & persist

Universe + FinnhubGoverned symbols · live trades

The universe service publishes validated, checksummed S&P 500 snapshots to SeaweedFS. Ingestion resolves the current snapshot and selects the product allowlist.

  • NVDA, AAPL and MSFT.
  • Normalize trades while preserving millisecond timestamps.
  • NYSE calendar controls collection hours.
KafkaDurable stock-trades events

Buffers trades between ingestion and Spark, enabling checkpoint-based recovery and replay.

  • Topic: stock-trades.
  • Low-memory local: two brokers, replication factor 2, minimum ISR 2, producer acks=all.
  • Both replicas must be available for writes with this policy.
Spark streamingValidate · aggregate · checkpoint

Reads Kafka records, validates event-time data and builds 30-minute OHLCV bars.

  • Valid trades → Bronze Delta.
  • Aggregates → Gold Delta.
  • Invalid or late records → dead-letter Delta.
  • Low-memory local: one worker, eight Gold shuffle partitions.
Delta + SeaweedFSVersioned tables & checkpoints

SeaweedFS provides S3-compatible object storage for Bronze trades, Gold bars, dead-letter tables and streaming checkpoints.

Delta versions provide reproducible inputs. Post-close processing drains available trades and recomputes closed bars from a pinned Bronze version.

↓ After the actual exchange close: persisted session data enters qualification.

02 / Qualify & publish features

Session qualificationGate · completeness & quality

Require full-session symbol/bar coverage, finite positive values and passing trade-gap checks. An incomplete session cannot silently become a production feature release.

Rolling features use bounded prior history. One qualified session does not establish enough training history for a production TFT.

Immutable releaseFeatures + qualification evidence

Packages session features with dataset identity, pinned Delta versions and qualification evidence. The publisher revalidates the release before committing it.

Collection-only operation stops at qualification. Publication requires explicit enablement.

PostgreSQLOffline history · publication ledger

The feature publisher commits qualified features and publication ledger state to PostgreSQL.

  • Qualified snapshots feed training.
  • Offline encoder history feeds serving.
  • Dataset lineage supports recovery and audit.
Feast → RedisOnline feature materialization

After the PostgreSQL commit, Feast materializes online features into Redis. Serving merges available online values with offline history.

PostgreSQL and Redis are not one atomic transaction. Online failures can be retried for the same dataset; freshness still gates forecasts.

↓ Qualified PostgreSQL history → training. PostgreSQL + Feast/Redis → serving feature readiness.

03 / Train & govern the model

TFT trainingTemporal splits · fitted transforms

Trains the Temporal Fusion Transformer on qualified historical snapshots using time-based train/validation separation.

Fitted preprocessing, encoders, normalizers and target contracts are preserved for consistent inference.

MLflow challengerVersioned artifacts & lineage

Records metrics, artifacts and dataset lineage, and registers an immutable model version assigned to @challenger.

PostgreSQL backs MLflow metadata; SeaweedFS stores model artifacts.

Governance approvalGate · first champion included

Requires baseline performance, minimum evaluation sample size, finite metrics, calibration and configured horizon/stability checks.

These checks apply to the first champion too. Approval alone does not move the serving alias.

Champion activationPrepare → alias → activate → verify

Prepares an approved model on serving replicas, moves @champion, activates the exact version and verifies readiness.

Activation failure triggers a rollback attempt. The serving model manager loads the governed artifact and validates its contract.

↓ Approved model version + fitted transforms → serving model manager.

04 / Serve post-close forecasts

Frontend → APIMetadata-driven product controls

The frontend reads /v1/metadata and requests forecasts from FastAPI. Production Traefik routes UI and API through a single domain.

The operator console uses separate authorization. Local development can access the API directly.

FastAPIGoverned model & request handling

Coordinates the loaded model, feature retrieval and inference. Forecast caches are model-version keyed and freshness checked.

Health/model endpoints expose readiness and model identity; the serving API exports operational metrics.

Feature readinessGate · history & freshness

Retrieves PostgreSQL encoder history plus available Feast online values and enforces the NYSE post-close freshness cutoff.

Stale features fail closed. A 30-minute bar interval does not promise intraday forecast publication.

Forecast responseCalibrated prices & quantile bands

TFT outputs are converted into price forecasts with calibrated quantile bands, market-calendar timestamps and model/feature provenance.

The response returns through FastAPI to the frontend, where users see predictions and freshness context.

↩ Forecast response → frontend. Publication, training and promotion remain independently gated.

Across all stages / Control & operations

Scheduling & lifecyclemacOS supervisor + Prefect

The local supervisor starts infrastructure before market open, checks progress and handles safe post-close shutdown. Prefect owns scheduled flows, retries and worker execution.

Local automation needs the Mac and Docker available. Downstream publication, training and activation need explicit enablement.

ObservabilityMetrics · alerts · progress checks

Job metrics flow through Pushgateway; API metrics are exposed by serving. Prometheus, Grafana and Alertmanager provide monitoring when enabled.

The supervisor checks offsets, Bronze progress, freshness, disk space and session cleanup.

Deployment boundariesLogical stages, not container count

SeaweedFS and PostgreSQL are shared backing services. Low-memory local collection excludes optional dashboards, materialization and training.

This is an architecture map, not live health telemetry or a claim of production qualification.
